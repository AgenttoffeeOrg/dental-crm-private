# k6 Load Testing Guide

## Overview

This project uses [k6](https://k6.io/) for load and performance testing to ensure the application can handle production traffic.

## Test Profiles

### 1. Smoke Test (`k6/smoke.js`)

**Purpose:** Quick availability check  
**Duration:** 1 minute  
**VUs:** 1 concurrent user  

**Use Case:**
- Pre-deployment sanity check
- Verify app is responding
- Quick health validation

**Thresholds:**
- Failed requests: <1%
- Response time p95: <500ms
- Checks passing: >95%

**Run:**
```bash
npm run k6:smoke
```

---

### 2. Load Test (`k6/load.js`)

**Purpose:** Simulate realistic production load  
**Duration:** 10 minutes  
**VUs:** Ramp 0→20→50→0  

**Stages:**
1. Ramp up to 20 users (2 min)
2. Sustain 50 users (5 min)
3. Ramp down to 0 (3 min)

**Thresholds:**
- Failed requests: <1%
- API response time p95: <300ms
- Page load time p95: <1000ms
- Checks passing: >99%

**Run:**
```bash
npm run k6:load
```

---

### 3. Stress Test (`k6/stress.js`)

**Purpose:** Find breaking point and capacity limits  
**Duration:** 10 minutes  
**VUs:** Ramp 0→50→100→150→0  

**Stages:**
1. Ramp to normal load: 50 VUs (2 min)
2. Increase to heavy: 100 VUs (3 min)
3. Push to stress: 150 VUs (3 min)
4. Ramp down (2 min)

**Note:** Thresholds are warnings only - test always passes for exploration.

**Run:**
```bash
npm run k6:stress
```

## Understanding Results

### Key Metrics

**HTTP Request Duration:**
- `avg`: Average response time
- `p50`: Median (50th percentile)
- `p95`: 95th percentile - 95% of requests faster than this
- `p99`: 99th percentile - 99% of requests faster than this
- `max`: Slowest request

**HTTP Request Failed:**
- Rate of failed HTTP requests (4xx, 5xx errors)
- Target: <1% for production

**Checks:**
- Rate of assertion checks that passed
- Target: >99% for production

**VUs (Virtual Users):**
- Number of concurrent simulated users

### Example Output

```
✓ homepage loaded
✓ dashboard loaded
✓ contacts API responded

checks.........................: 99.5% ✓ 1990 ✗ 10
http_req_duration..............: avg=245ms p95=389ms
http_req_failed................: 0.1%  ✓ 2 ✗ 1998
http_reqs......................: 2000
vus............................: 50
```

**Interpretation:**
- ✅ 99.5% checks passed (excellent)
- ✅ Average response: 245ms (fast)
- ✅ P95 response: 389ms (good)
- ✅ Only 0.1% failed requests (excellent)

## Thresholds Explained

### Performance Thresholds

**Smoke Test:**
- `http_req_failed<0.01`: Less than 1% of requests fail
- `http_req_duration:p95<500`: 95% of requests complete in <500ms

**Load Test:**
- `http_req_failed<0.01`: Less than 1% fail rate
- `http_req_duration{route:~.*api.*}:p95<300`: API calls <300ms at p95
- `checks>0.99`: 99% of assertions pass

**Stress Test:**
- Thresholds are warnings only
- Test explores limits without failing
- Used for capacity planning

## Running Locally

### Prerequisites

Install k6:

**macOS:**
```bash
brew install k6
```

**Linux:**
```bash
sudo gpg -k
sudo gpg --no-default-keyring --keyring /usr/share/keyrings/k6-archive-keyring.gpg --keyserver hkp://keyserver.ubuntu.com:80 --recv-keys C5AD17C747E3415A3642D57D77C6C491D6AC1D69
echo "deb [signed-by=/usr/share/keyrings/k6-archive-keyring.gpg] https://dl.k6.io/deb stable main" | sudo tee /etc/apt/sources.list.d/k6.list
sudo apt-get update
sudo apt-get install k6
```

### Run Tests

```bash
# Set environment variables
export BASE_URL="https://dental-crm-private-production.up.railway.app"
export TEST_EMAIL="your-email@example.com"
export TEST_PASSWORD="your-password"

# Run smoke test
npm run k6:smoke

# Run load test
npm run k6:load

# Run stress test  
npm run k6:stress
```

## CI/CD Integration

### When Tests Run

**On Pull Requests:**
- Smoke test only (quick, 1 minute)
- Validates app is responsive
- Blocks PR if smoke test fails

**On Merge to Main:**
- Smoke test + Load test
- Full performance validation
- Generates summary report

**Scheduled (Daily at 1 AM UTC):**
- Full load test
- Monitors production performance
- Tracks performance trends

### Viewing Results

**In GitHub Actions:**
1. Go to Actions tab
2. Click on "k6 Load Tests" workflow
3. View logs for detailed metrics
4. Download `k6-results` artifact for JSON summary

**On PR:**
- Automated comment with smoke test results
- Shows if thresholds were met
- Links to full reports

## Customizing Tests

### Adjust Load Levels

Edit `k6/load.js`:

```javascript
export const options = {
  stages: [
    { duration: '2m', target: 20 },  // ← Change target VUs
    { duration: '5m', target: 50 },  // ← Change sustained load
    { duration: '3m', target: 0 },
  ],
};
```

### Modify Thresholds

Edit threshold values:

```javascript
thresholds: {
  http_req_failed: ['rate<0.01'],      // ← Change to 0.05 for 5%
  'http_req_duration': ['p95<300'],    // ← Change to 500 for slower
},
```

### Add More Endpoints

Edit the test scenario:

```javascript
export default function(data) {
  // Add your endpoint here
  http.get(`${baseUrl}/my-endpoint`, getRequestParams('my-endpoint', auth));
}
```

## Troubleshooting

### Issue: Tests Fail with 401 Unauthorized

**Cause:** Authentication not working  
**Fix:**
1. Verify `TEST_EMAIL` and `TEST_PASSWORD` are correct
2. Check login endpoint in `k6/helpers.js`
3. Verify credentials work in browser

### Issue: High Failure Rate

**Cause:** Application errors or timeout  
**Fix:**
1. Check application logs
2. Verify database connection
3. Check if app is actually running
4. Reduce VUs if overwhelming the server

### Issue: Slow Response Times

**Cause:** Performance bottleneck  
**Fix:**
1. Check database query performance
2. Review API endpoint implementations
3. Check Railway resource allocation
4. Consider caching strategies

## Best Practices

1. **Run smoke before deploy** - Quick validation
2. **Run load tests on staging** - Before production
3. **Monitor trends** - Track performance over time
4. **Adjust based on traffic** - Match VUs to real usage
5. **Don't stress production** - Use staging for stress tests
